# Status

Slices 01-15 complete: a gin+templ+GORM framework whose public API (New, Wrap, Bind, Stack, Chain) stands over a db package. The demo app (cmd/sheidan) serves a templ home page, a reactive notes list and detail page driven by a GopherJS client (store, scheduler, minimal-diff reconciler), and note create/read/update/delete. The default middleware chain is twenty-one named slots, each with a lane taken from the name prefix, a fixed ordinal, and a kind. Builders shape chains with Enable, Disable, Configure, Insert, and Remove, rejecting malformed operations at compile time, and Chain produces per-group filtered copies. Slots 1 and 2 are seated: request.id stamps or propagates an identifier, and logging.slog writes outcome-graded records (info, warn, error) bearing it, staying silent for preflight and static, web, and debug traffic. A guarded recovery ahead of the chain records panics through the same writer. The demo's pprof group is dark by default and switches on with SHEIDAN_DEBUG, optionally guarded by SHEIDAN_DEBUG_TOKEN.

webbuild/ self-bootstraps GopherJS: it provisions a Go 1.21.13 SDK into the user cache on demand and builds the gopherjs CLI with Go 1.21-1.26 (CLI binaries made with newer toolchains panic on the js package). The transpiled web/web.js is gitignored and served by the demo.

Next (slices 16-21), filling the remaining lanes in order: intake guards and CORS (maintenance, banned IPs, POST size, header validation, string trimming, cors). Sessions and cookie finalization. CSRF and signed requests. Rate limiting, authorization, deadline-bounded responses. Localized views, substitution bindings, flash-error decor, response caching. Static serving and graceful shutdown.
